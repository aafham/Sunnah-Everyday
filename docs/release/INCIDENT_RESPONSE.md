# Incident Response

## Scope

This runbook covers security, content, source-rights, privacy, availability and
release incidents. It complements the correction policy and never authorises a
reviewer/publisher to bypass mandatory approval controls.

## Immediate actions

1. Record time, reporter/source, affected item/version/build/track, impact and
   evidence without placing secrets or personal data in public logs.
2. For a plausible content/right/privacy risk, suspend affected daily schedule
   and remove it from the next public bundle/widget path.
3. Limit system access using least privilege; rotate exposed secrets through
   approved secret storage, never by committing replacements.
4. Escalate to the appropriate qualified human reviewer, rights owner, owner,
   or platform administrator.

## Investigation and remediation

- Preserve immutable audit data and affected version IDs.
- Use a correction/withdrawal case and new reviewed version; do not edit a
  published record in place.
- Test cache, widget, deep-link and offline behaviour after a withdrawal.
- For an uploaded build, use the actual Play Console state and documented
  platform options; do not claim a halt or rollback until confirmed.

## Communication and closeout

Share only approved, minimal public information. Record corrective action,
review decisions, test evidence, release status, and preventive follow-up.
Close only after the responsible reviewer/owner accepts the result and public
state has been verified where applicable.
