# Architecture and Delivery Decisions

| ID | Decision | Status | Rationale | Consequence |
| --- | --- | --- | --- | --- |
| ADR-001 | Android-first Flutter monorepo | Accepted | The owner specified Flutter Android-first while preserving iOS portability | Mobile and admin share Dart packages; Android widget remains native Kotlin |
| ADR-002 | Public user has no mandatory account | Accepted | Privacy-first MVP and lower friction | Bookmarks/reflections remain local; Supabase Auth is for admins only |
| ADR-003 | Religious content is data, never generated UI copy | Accepted | Prevents invented/unsourced claims | Only approved bundles are public; demo content is explicitly non-publication |
| ADR-004 | Database/server publication gate is authoritative | Accepted | Flutter UI cannot be the only protection | SQL/RLS/functions must enforce approvals, rights, grades and immutable versions |
| ADR-005 | Daily Feed permits only SAHIH/HASAN evidence | Accepted | Required content safety rule | Validation rejects other grade values even if the model supports them |
| ADR-006 | Drift is the offline source of last-known-good data | Accepted | Offline search and daily delivery require relational local state | Bundle application must be transactional/checksummed and support withdrawal |
| ADR-007 | Four-tab information architecture | Accepted | Keeps the mobile experience calm and focused | Hari Ini, Teroka, Simpanan and Tetapan only |
| ADR-008 | Kotlin/Jetpack Glance widget bridge | Accepted | Native Android widgets need reliable lifecycle/resize support | Widget data must be safe cached approved content with deep links |
| ADR-009 | No analytics or ad SDK by default | Accepted | Privacy and Play Data Safety accuracy | Any future telemetry needs explicit approval and policy/audit update |
| ADR-010 | Feature branch and truthful release records | Accepted | Repository may be shared; external access is unverified | No direct main commit, force push, assumed push, or assumed Play state |
| ADR-011 | Public repo visibility is unchanged | Accepted | Remote is already public and owner did not request a change | Do not place sensitive content or credentials in the repository |
| ADR-012 | BE-01 begins with a deny-by-default database baseline | Accepted | No public/admin data path may exist before role, rights and publication controls are audited | All application tables force RLS and revoke table access from `PUBLIC`, `anon` and `authenticated`; BE-02 must add narrowly scoped policies before any access can work |
| ADR-013 | Content intake starts as a draft-only contract | Accepted | Technical templates must not become a path for AI-generated or unreviewed religious content | Header-only CSV/JSON templates, pure-Dart models and directory controls accept only `STAGING`/`DRAFT` metadata; no candidate can schedule, approve, publish or create a public bundle |
| ADR-014 | CNT-02 validation is read-only and import fails closed | Accepted | A local CSV check cannot replace authenticated roles, audit history, human decisions or server publication gates | The CLI validates canonical CSV/schema/relational constraints and reports safe codes only; `import_content.mjs` writes nothing until BE-03 supplies the authoritative workflow |
| ADR-015 | Flutter tests use a private shared deterministic harness | Accepted | The repository root is not a Flutter package, and repeated ad hoc viewport/router setup makes responsive widget tests fragile | `packages/testing_utils` owns generic viewport/media/transition helpers; each app owns its own setup; root scripts run every target while REL-01 remains responsible for CI |
| ADR-016 | GitHub Quality CI is read-only and fails closed for release actions | Accepted | Current content, signing, Play access and release gates are incomplete, so automation must prove quality without creating a path to publish | The workflow has only `contents: read`, SHA-pinned reviewed actions, no secrets/artifacts/deployment, and can build only a debug APK plus ephemeral web output; REL-03/REL-04 retain signing and Play authority |
| ADR-017 | Onboarding and UI preferences are device-local and allowlisted | Accepted | The language choice and accessibility settings must survive restart without introducing a content or account store | `SharedPreferencesWithCache` receives only onboarding completion, locale, theme, reduced motion and text scale; initialization failure uses an in-memory session fallback, and no content/source/reviewer/reflection/credential value is eligible for storage |
| ADR-018 | Daily presentation fails closed before a verified public bundle exists | Accepted | A navigable Daily surface must not become an accidental draft or unreviewed-content path | The built-in reader returns only an unavailable state with no content identifiers or claim-bearing fields; it must not read staging, approved directories, draft CSV or network content until the authoritative bundle gate exists |
| ADR-019 | Generic RTL layout baseline is separate from language/content delivery | Accepted | Directional UI needs coverage now, while no Arabic locale, font, approved text, source rights or human language review is available | PDX-03 uses directional page insets, Material's direction-aware back affordance and a test-only RTL override; the installed shell remains exactly BM/English and no Arabic UI/content or publication path is enabled |
| ADR-020 | Bounded Android secure storage is a narrow private-reflection exception, not the future content cache | Accepted | A person needs a local, deletable free-text reflection before an approved bundle and relational data contract exist, but an unbounded key-value store would conflict with the planned Drift architecture | The current envelope is capped at 50 reflections of 500 characters, uses an Android-only isolated `flutter_secure_storage` namespace with `resetOnError: false`, never falls back to browser/plaintext/in-memory storage in the installed app, and permits only scoped recovery deletion if unreadable. It has no content ID, network, admin, analytics or export path. Drift remains the future transactional store for approved bundles and content-bound bookmarks/history/practice tracking; this does not claim secure erasure or complete Data Safety review. |
| ADR-021 | External deep-link input is reduced to static fail-closed routing before content delivery exists | Accepted | Android intent URIs are untrusted and a verified public-bundle/content-reference contract does not yet exist | Only strict `sunnah://daily`, `sunnah://content` and `sunnah://correction` URI shapes are recognised. Daily/content map to the existing static unavailable status, correction/invalid/unknown external URIs map to a generic localized recovery page, and all external routes are intercepted before path-based onboarding. Opaque tokens never become route parameters, UI text, storage, network, analytics or logs. Content-bound delivery remains DEL-04/BE-04 work. |
| ADR-022 | QLT-04 source-audit evidence is a regression baseline, not release evidence | Accepted | Direct manifests, static source and a debug artifact can catch scope drift cheaply, but cannot establish runtime, transitive-SDK, signed-build, privacy or performance facts | CI records reviewed direct dependencies, static network/asset boundaries and main/debug manifest observations. Re-audit when dependencies, manifests, network/storage code, assets/fonts/content boundaries or release configuration change; signed release, Data Safety, privacy, device and performance gates remain separate |
